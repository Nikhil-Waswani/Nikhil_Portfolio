3-Day AQI Forecaster

A serverless, fully automated machine learning system that forecasts Air Quality Index 3 days in advance

An end-to-end ML pipeline for Khairpur, Pakistan that ingests live weather and pollutant data every hour, retrains three competing models daily, and serves a 3-day AQI forecast through a live Streamlit dashboard — with zero servers to manage.

Python Scikit-learn XGBoost Firebase Streamlit GitHub Actions

About the Project

Problem it solves: Air quality in many cities changes quickly and unpredictably, but most residents only have access to the current AQI reading, not where it's heading. Knowing the trend a few days ahead helps people plan outdoor activity and manage health risks.

Why it was built: I wanted to build a complete, production-style ML system rather than a one-off notebook — one that collects its own data, retrains itself, and stays live without me touching a server. It became a hands-on study in MLOps fundamentals: automated pipelines, feature stores, and continuous model evaluation.

Project Goal: Predict the Air Quality Index for Khairpur, PK for the next 3 days using live OpenWeather data, automatically picking the best-performing model out of three candidates every single day.

Technology Stack

Each layer of the pipeline was chosen to stay free, simple, and fully automatable:

Python

Core language for the data pipeline, feature engineering, and model training scripts.

Firebase Firestore

Serverless NoSQL feature store holding both live hourly readings and a year of backfilled historical data.

Streamlit

Live web dashboard showing current conditions, the 3-day forecast, and model performance metrics.

GitHub Actions

Scheduled CI/CD jobs that run the hourly ingestion and daily retraining — the entire "infrastructure" for this project.

Scikit-learn & XGBoost

Ridge Regression, Random Forest, and XGBoost trained daily, compared by RMSE, with the best one promoted automatically.

SHAP

Model interpretability layer used to confirm and explain which features actually drive the AQI prediction.

Key Features

A complete, self-sustaining ML system rather than a static prediction script:

Hourly Data Collection

Automatically pulls live air pollution and weather data from OpenWeather every hour and writes it to Firestore.

Daily Auto-Retraining

Retrains 3 candidate models every day on the latest combined dataset and promotes the lowest-RMSE model automatically.

3-Day AQI Forecast

Projects pollutant trends forward to estimate AQI for the next 3 days, displayed with category labels (Good → Hazardous).

Live Dashboard

Streamlit app showing current conditions, the 3-day outlook, a 24-hour AQI trend chart, and live model metrics.

Feature Store Pattern

Separates live hourly data from a year of historical backfilled data in Firestore, mirroring real-world ML feature store design.

Explainable Predictions

SHAP analysis confirms PM2.5 as the dominant driver of AQI, validating the model against the actual EPA formula.

Model Performance

Three models are trained and compared automatically every day; the best one (lowest RMSE) is promoted to production:

Model RMSE MAE R²
Ridge Regression 21.22 12.40 0.877
Random Forest 2.28 0.10 0.999
XGBoost 6.25 0.80 0.989

SHAP Feature Importance

PM2.5 concentration is by far the strongest predictor, which lines up with the US EPA AQI formula being derived directly from PM2.5 — a good sanity check that the model is learning the right relationship rather than a spurious one.

Challenges & Learning

Staying Fully Serverless

Designing every stage — ingestion, training, and serving — to run on free-tier GitHub Actions and Firebase, with no server I had to manage or pay for, took careful scheduling and state design.

Feature Store Design

Splitting live and historical data into separate Firestore collections, then merging and deduplicating them at training time, mirrors how production feature stores actually work.

Forecasting Without a Forecast API

The free OpenWeather tier only gives current conditions, not future weather — so the 3-day outlook is generated by projecting pollutant trends forward rather than a true multi-step forecast.

Key Learnings

  • Hands-on experience with MLOps fundamentals: CI/CD for ML, automated retraining, model promotion
  • Practical use of Firebase Firestore as a lightweight feature store
  • Comparing regression models rigorously using RMSE/MAE/R² rather than picking one by default
  • Using SHAP to validate that a model has learned a sensible, explainable relationship
  • Recognizing the gap between a "live dashboard" and a true time-series forecast — and being upfront about that distinction
